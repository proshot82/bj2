# MIGRATION.md — переезд «Латунный янычар 2.0» в Claude Code

## 0. Контекст проекта (важно, не потерять)

«Латунный янычар 2.0» — это **мультяшный 1080p-ремейк первого,
пиксельного «Латунного янычара» (v1.0.0, 640×360)**, а не отдельная
игра. Дизайн переработан по критике v1 (см. GDD, §0). Ассет-пайплайн
(генерация cartoon-арта пользователем во внешнем генераторе по
ASSET_SPEC) уже отработан: ассеты сгенерированы, приняты, игра собрана
как v2.0.0. Никакой отдельной будущей задачи «промпт-пайплайн рескина»
не существует — из рескин-работы остался только пункт 5 ниже
(два титульных арта → релиз 2.0.1).

Пакет: `bj2-repo.tar.gz` — полный репозиторий проекта **с git-историей**
(включая `work/` с оригиналами-карантином и `work/autoplay_full.json`).

## 2. Зависимости окружения

| Что | Зачем | Установка (Ubuntu/Debian) |
|---|---|---|
| LÖVE 11.5 | рантайм игры | `apt install love` (проверить `love --version` = 11.5) |
| luajit | синтакс-чек, юнит-тесты ядра, фаззер | `apt install luajit` |
| xvfb | headless-прогоны | `apt install xvfb` |
| wine (9.x) | верификация Windows-сборки | `apt install wine` |
| python3 + PIL, numpy, scipy | генераторы, промеры, гейты | `pip install pillow numpy scipy --break-system-packages` |
| zip/unzip | .love и портативный ZIP | `apt install zip unzip` |

Wine из кириллических путей требует UTF-8 локали:
`LANG=C.UTF-8 LC_ALL=C.UTF-8` перед `wine …`.

## 3. Верификационный конвейер (Definition of Done)

Запускать из корня репозитория, по порядку:

```bash
luajit tools/test_state.lua                    # ядро: солвер, негативы, roundtrip
python3 tools/validate_puzzles.py              # GATE1: граф, разрешимость, герринги
python3 tools/gen_scene.py && python3 tools/gen_texts.py
python3 tools/validate_scene.py                # GATE2: сцена/тексты/тени/иконки
python3 tools/check_fonts.py                   # гейт шрифтов: тофу-глифы (р.19)
xvfb-run -a -s "-screen 0 1920x1080x24" love . --selftest      # смок
rm -rf ~/.local/share/love/BrassJanissary2     # чистый сейв
python3 tools/gen_autoplay.py
xvfb-run -a -s "-screen 0 1920x1080x24" love . --autoplay work/autoplay_full.json
python3 tools/gates.py                         # пиксельные гейты по скринам
luajit tools/fuzz_state.lua                    # 3×25000 + анти-софтлок + гейт покрытия веток
luajit tools/trace_solver.lua && python3 tools/clue_audit.py
python3 tools/gen_walkthrough.py               # спойлеры → docs/ (не в чат!)
python3 tools/gen_verify_sheets.py             # verify-листы зон → смотреть глазами
xvfb-run -a -s "-screen 0 1920x1080x24" love . --autoplay work/ap_smoke.json  # letterbox-смок
python3 tools/test_negatives.py                # негативы: гейты обязаны ПАДАТЬ на порче
```

Негативы идут последними намеренно: им нужны и данные, и оба сценария из
`work/`, и каталог кадров, то есть весь конвейер целиком. Гейт, зелёный на
данных без игры, — украшение, поэтому каждый проверяется в обратную сторону:
данные (или исходник) портятся одной точечной мутацией, гейт обязан вернуть
rc≠0 и назвать причину, а оригиналы восстанавливаются со сверкой md5. Полный
прогон ≈2 минуты; `--fast` пропускает движковые кейсы и честно перечисляет,
что осталось непроверенным.

Про letterbox-смок. Сценарий `work/ap_smoke.json` выводится из полного
`gen_autoplay.py`-ом (в `work/` руками ничего не кладём — каталог не под
контролем версий, и на чистом клоне шага просто не было бы). Разрешение окна
меняет сам сценарий: `op resize` трижды по ходу прогона — 1600×1000, 1920×864,
1500×900 (полосы сверху/снизу, слева/справа и дробная), после чего клики идут
по тем же мировым точкам и обязаны попадать через пересчёт. Экран xvfb здесь
1920×1080 намеренно: X разрешает окну быть больше экрана, поэтому прежний
`--screen 1536x864` окно не ограничивал и смок шёл в том же разрешении, что и
основной гаунтлет — то есть не проверял ничего.

Упаковка: см. `docs/BUILDLOG.md`, раздел «Фаза 6» (fuse exe, DLL,
README/LICENSE/VERSION, zip -9, wine-прогон из кириллического пути,
SHA-256). **Portable-only: никаких инсталляторов.**
