## 2. Где что лежит и как туда писать

Репозиторий живёт **только на Windows-машине автора**: `C:\Янычар\bj2`
(подключённая папка — `C:\Янычар`). Через мост она видна как
`/sessions/<id>/mnt/Янычар/bj2`. Git есть только там.

Рабочая копия в облаке — временная, её надо поднимать заново каждую сессию:

```bash
# на устройстве (device_bash), из C:\Янычар\bj2:
tar czf ../bj2_src.tar.gz --exclude=.git --exclude=work --exclude=dist .   # ≈72 МБ
# затем device_stage_files на C:\Янычар\bj2_src.tar.gz и в облаке:
mkdir -p /tmp/bj/bj2 && tar xzf <staged>/bj2_src.tar.gz -C /tmp/bj/bj2
# после переноса — архив в C:\Янычар\_to_delete\
```

В облачной копии нет `.git`, `handoff/` и `dist/` — и не надо: гейтам они не
нужны, а git всё равно только на ПК.

**Запись на устройство.** Монтирование запрещает `unlink`, `rm` и
переименование поверх существующего файла. Рабочий способ ровно один:
правка в облаке → `zip` → `SendUserFile` → `device_commit_files` архива в
`C:\Янычар\` → на устройстве `unzip -p архив member > target` (запись
усечением, не заменой inode) → сверка md5 с облаком. Мусор — не удалять, а
переносить в `C:\Янычар\_to_delete\`, автор чистит сам.

`device_stage_files` / `device_commit_files` принимают **windows-пути**
(`C:\Янычар\...`), `device_bash` — **posix-путь монтирования**. Таймаут
`device_bash` — максимум 45 с. VM устройства засыпает и отвечает «Workspace
still starting» — подождать 20–35 с и повторить. **На устройстве нет ни
`luajit`, ни `love`** — лугейты гоняются только в облаке.

**Git через монтирование** (рецепт из AGENTS.md §«Известные особенности»,
проверен в р.18 и р.19): читать с `GIT_OPTIONAL_LOCKS=0`; индекс держать вне
монтирования — `export GIT_INDEX_FILE=/tmp/bj_idx` + `git read-tree HEAD`,
дальше `add`/`status`/`commit` обычным порядком, в конце `cp /tmp/bj_idx
.git/index`. После коммита останется мусор `.git/objects/*/tmp_obj_*` и
`.git/HEAD.lock` — перенести в `_to_delete/`, иначе следующая операция
упрётся в лок. Приёмка: пустой `git status --porcelain` и чистый `git fsck`.

Хвост каждого коммита:

```
Co-Authored-By: Claude <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_<id>
```

## 3. Жёсткие правила (нарушение = ущерб, не стилистика)

1. **Спойлеры.** Коды, глиф-карта, порядок стенда не появляются ни в чате, ни
   в отчётах, ни в коммитах — только в `design/puzzles.json` и
   `docs/WALKTHROUGH_SPOILERS.md`. Сид генератора эквивалентен ответам; в
   любых дампах порядок стенда маскировать.
2. **Релиз — только по слову «собирай».** Никаких ZIP «на всякий случай».
3. **`design/scene.json` и `design/texts.json` генерируются** — руками не
   править никогда, править `tools/gen_scene.py` / `tools/gen_texts.py` и
   регенерировать. `puzzles.json` — особый случай: штатный regen только
   `python3 tools/gen_puzzles.py --pin` (голый запуск скрипт отклоняет сам,
   rc=2). Новые ответы — осознанно, `--new-answers --force`.
   Контрольные md5 неприкосновенных файлов:
   `design/puzzles.json` = `4eb33ed5d9da8aa5b3331b08fe27af11`,
   `tools/gen_puzzles.py` = `ace79fbe506a2dda262abc6e45c8150e`,
   `docs/WALKTHROUGH_SPOILERS.md` = `8ca032294f3251d847c2265a1d9953c8`.
4. **Мир не трясти** — тряска только у плашек UI. Прямая цитата автора:
   «нет-нет, не надо трясти мир, тряски плашек было вполне достаточно».
5. **Сюжетная типографика не рисуется в арте** (принцип 9): коды, даты,
   номера, легенды рендерит движок, бумаги и таблички в арте чистые.
6. **Зоны:** минимальная сторона 44 px, hit-список сортируется по площади по
   возрастанию (меньшая зона выигрывает), центры не перехватываются — следит
   GATE2. Попадание клика по арту доказывают промеры numpy и verify-листы, а
   не взгляд на превью.
7. **Ассеты генерирует автор** (изображения — ChatGPT по моему ASSET_SPEC с
   кроп-референсами, музыка — Suno) и кладёт в `C:\Янычар\` рядом с `bj2`.
   Перед правкой любого ассета оригинал уходит в карантин `work/orig_*`;
   после интеграции исходник из корня убрать.

## 4. Что открыто прямо сейчас

**Главное — замечание 3 раунда 19: два новых ассета.** Автор прав, что
открытые ящики Иры и верстака нелепы: это приклеенные катауты-заплатки на

| `zoom_ira_drawer.png` | `assets/gfx/zooms/zoom_ira_drawer.png` |
| `zoom_wb_drawer.png` | `assets/gfx/zooms/zoom_wb_drawer.png` |

Полная спецификация с готовыми промптами — `docs/ASSET_SPEC_R19.md`,
референсы — `work/spec_r19/` (каталог вне контроля версий; если пропал —
нарезать заново из `zoom_drawer_keypad.png`, `zoom_workbench.png`,
`zoom_lap_drawer.png`). Там же §7 — точный план проводки сцены после приёмки:
какие хотспоты меняют `doc=`/`node=` на `goto=`, куда переезжает `take_wrench`,
какие два катаута уходят в `work/orig_r19_retired/`. **Проводку делать только

из манифеста существовал. В `zoom_wb_drawer.png` разводной ключ впечатан в
арт (иконка инвентаря 128×128, растягивать вчетверо нельзя), поэтому при
интеграции нужны три строки в `src/ui.lua`: флаг `leave_zoom` у хотспота,
уводящий из зума после срабатывания узла.

**Хвост корзины C раунда 18**, до которого раунд 19 не дошёл: хотспот

## 5. DoD-конвейер

Полный список команд — `MIGRATION.md` §3. Прогон занимает ≈6–8 минут в
облаке, гонять целиком после любой правки данных или кода, а не выборочно.
Порядок принципиален: негативы идут последними, потому что им нужны и данные,
и оба сценария из `work/`, и каталог кадров.

Результат раунда 19 (эталон, с чем сравнивать): солвер — победа за 52 шага;
GATE1 — документов 17; GATE2 — хотспотов 117, катаутов 53, реплик 329, мат 0 %,
плоских силуэтов 0, худший запас ×1.39; гейт шрифтов — 3 шрифта, 155 символов;
selftest — ассетов 148 нужных при 150 в дереве; гаунтлет — 375 шагов, бейджи
2/2; пиксельные гейты — контрасты 13.0–14.7:1, яркость A-ночь 47 %, B-ночь
13 % (порог для B сознательно ослаблен до 8 %); fuzz 3×25000; verify-листы —
16 видов, 74 катаута, ниже порога 0; letterbox-смок — 353 шага; негативы —
20 из 20.

Гейт, зелёный на данных без игры, — украшение. Поэтому каждый новый гейт
обязан получить негатив в `tools/test_negatives.py`: точечная мутация данных
или исходника, гейт возвращает rc≠0 и называет причину, оригинал
восстанавливается со сверкой md5.

## 6. Грабли, на которые уже наступали

- **Тофу-глифы.** LÖVE на отсутствующем глифе молча рисует `.notdef`, а в
  Neucha он пустой — символ исчезает бесследно, и это не видно ни в одном
  логе. Раунд 19 нашёл шесть дыр разом. Сторожит `tools/check_fonts.py`;
  правило «символ обязан рисоваться всеми тремя шрифтами», потому что одна
  строка уходит и в диалог (PTSans), и в бумагу (Neucha).
- **Автоплей самосогласован** — он кликает центры зон из тех же данных, что
  рисуют зоны. Совпадение зоны с артом доказывают только verify-листы и
  промеры. Именно поэтому смещение зон на зумах дожило до автора: генератор
  verify-листов рисовал три вида, только комнаты, и ни одного зума.
- **Правая треть ночного офиса**: детали арта примерно на 50 px правее данных
  хотспотов (пред-существующий рассинхрон, QA_JOURNAL р.10).
- **Инструмент точечной правки на монтировании дважды усекал** большие
  кириллические файлы. Крупные правки генераторов — атомарными
  python-скриптами с `ast.parse` после записи; после любой правки — regen и
  гейты.
- **`AGENTS.md` и этот файл обязаны быть закоммичены.** Первая версия жила
  untracked и потерялась при синхронизации рабочих копий.
- Bash-инструмент в облаке сбрасывает cwd после каждого вызова — каждая
  команда начинается с `cd /tmp/bj/bj2`.
